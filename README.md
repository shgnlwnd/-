# 복숭아 가격 기능 전달 사항

앱에서 사진으로 판정한 복숭아에 도매시장 시세를 함께 보여 주기 위한 서버와 안드로이드 연결 코드임.

## 1. 한눈에 보기

- 가격 서버 주소: `https://peach-price-api.onrender.com`
- 앱이 할 일: Firebase 로그인 토큰을 붙여 `/prices`를 부르고, 받은 값으로 화면을 그림.
- 서버·자료 수집·Firebase 저장은 모두 준비 완료. 앱 쪽에서는 아래 3절만 하면 됨.

```
공공데이터포털 API ─(매일 자동 수집)─▶ Firebase Firestore ─▶ Render 가격 서버 ─▶ 앱
```

## 2. 보여 주는 가격의 뜻

- 도매시장 표준코드에 '미홍' 품종이 없음. 그래서 **같은 시기(6/10~7/10) 전국 조생 백도계 복숭아 시세**(품종명 복숭아(일반)·백도·기타)로 대신함.
- 앱 화면에는 "미홍 가격"이 아니라 응답의 `basis` 문구("같은 시기 조생 백도계 복숭아 시세…")를 함께 표시해야 함.
- 기준은 판매자(농가)용 도매 경락가임. 소매가가 아님.
- 상자 크기별로 kg당 가격이 크게 달라서(2.5 kg 상자 약 6,000원/kg, 5 kg 상자 약 3,000원/kg) 상자 크기를 골라서 보여 줌.

## 3. 안드로이드 앱에 넣기

자세한 순서는 [`android/README_ANDROID.md`](android/README_ANDROID.md)에 있음. 요약하면 다음과 같음.

1. [`android/PeachPriceApi.kt`](android/PeachPriceApi.kt)를 앱 프로젝트에 넣고 `package` 이름을 앱에 맞게 바꿈.
2. app 모듈 `build.gradle`에 Retrofit·OkHttp·coroutines-play-services 의존성을 추가하고 Sync함.
3. `AndroidManifest.xml`에 인터넷 권한이 있는지 확인함.
4. 로그인된 상태에서 `PeachPriceRepository().getPrices(size = "4")`를 호출함.

## 4. API 요약

`GET /prices` (헤더 `Authorization: Bearer <Firebase ID 토큰>` 필수)

| 파라미터 | 뜻 | 예 |
|---|---|---|
| `size` | 상자 kg (2, 2.5, 3, 4, 4.5, 5, 10) | `4` |
| `market` | 도매시장 코드, 비우면 전국 (`/markets`로 목록 확인) | `380401`(진주) |
| `date` | 시험용 기준일, 비우면 오늘 | `2026-06-25` |

응답의 주요 값:

| 필드 | 화면에서 쓰는 곳 |
|---|---|
| `current` | 금일 시세 (휴장일이면 직전 경매일 값, `date`에 실제 날짜) |
| `vs_last_year_pct` | 작년 같은 날 대비 % (가장 크게 표시) |
| `past_years` | 작년·재작년·재재작년 같은 날 가격 |
| `avg_3y_won_per_kg` | 지난 3년 평균선 |
| `series` | 추세 그래프용 연도별 날짜·kg당 가격 |
| `in_season` | false면 비수기. 지난 시즌 마지막 날(7/10) 값이 나옴 |

## 4-1. 가격 예측 API (머신러닝)

`GET /forecast?harvest_date=2027-06-22&size=4` (헤더 `Authorization: Bearer <Firebase ID 토큰>` 필수)

- 예상 수확일 앞뒤 3일(총 7일)의 일별 **예상 상자 가격**, **가격 범위(하한~상한)**, **예측 오차(%)**를 돌려줌.
- `today`: 시험용 기준일(비우면 오늘). 이 날짜 이후 자료는 쓰지 않고 예측함.
- 안드로이드에서는 `PeachPriceRepository().getForecast("2027-06-22", "4")`로 부름.

응답의 주요 값:

| 필드 | 뜻 |
|---|---|
| `days[]` | 7일 각각의 `date`, `weekday`, `box_price`(예상가), `box_low`~`box_high`(범위), `expected_error_pct`(과거 평균 오차) |
| `days[].is_harvest_day` | 예상 수확일 표시 |
| `days[].market_closed` | 일요일(경매 거의 없음) 표시 |
| `best_day` | 7일 중 예상가가 가장 높은 날 (일요일 제외) |
| `level_source` | 올해 가격 수준을 무엇으로 잡았는지 (시즌 전: 지난 3년 평균 / 시즌 중: 올해 시세와 섞음) |
| `error_by_horizon` | 며칠 앞을 예측하느냐에 따른 과거 평균 오차 |

모델 요약:

- 출하기 안에서 날짜·요일·상자 크기에 따라 가격이 어떻게 움직이는지를 Gradient Boosting 회귀로 학습함.
- 여기에 올해 가격 수준(시즌 전에는 지난 3년 평균, 시즌 중에는 올해 최근 시세를 점점 더 많이 반영)을 곱해 예측함.
- 2020~2026년 실제 경매 자료로 해마다 하나씩 빼고 맞혀 본 평균 오차: 1~3일 앞 약 12%, 4~10일 앞 약 16%, 11~30일 앞 약 16%. 가격 범위는 이 오차의 10~90% 구간임.
- 첫 호출 때 모델을 학습하므로(하루 한 번) 응답이 수십 초 걸릴 수 있음.

## 5. 꼭 지킬 것

- **Firebase 프로젝트:** 앱 로그인은 반드시 **sfm-work** 프로젝트여야 함. 다른 프로젝트 토큰은 "로그인 정보가 올바르지 않습니다"(401)로 거절됨.
- **첫 호출 지연:** 무료 서버라 한동안 요청이 없으면 잠듦. 깨어나는 첫 호출이 최대 50초 걸리므로 로딩 표시가 필요함. 코드는 70초까지 기다리게 되어 있음.
- **시험용 날짜:** 지금은 비수기라 `date = "2026-06-25"`로 시험함. **출시 때는 `date = null`로 바꿀 것.**
- **현재 자료 범위:** 2024~2026년 출하기 자료만 저장되어 있음. 2026-06-25 기준으로 시험하면 재재작년(2023)은 "자료 없음"으로 나오며 정상임.
- **비밀값 불필요:** 공공데이터포털 인증키와 Firebase 서비스 계정 키는 앱에 넣지 않음. 서버와 GitHub에만 있음.

## 6. 운영 정보 (참고)

- 서버: Render 무료 웹 서비스 `peach-price-api`
- 매일 수집: GitHub 저장소 `shgnlwnd/-`의 Actions "복숭아 가격 수집"이 출하기 동안 매일 16:10(한국 시간)에 실행됨. 비수기에는 바로 끝남.
- 저장 위치: Firestore `peach_daily` 컬렉션 (문서 하나 = 하루치, 상자 크기별·시장별 집계)
- 서버 코드: 이 저장소 최상위 폴더(`app.py`, `collect.py`, `peach_price/`). 자세한 설명은 [`SERVER.md`](SERVER.md)
- **자동 수집 다시 켜기:** 공개 저장소는 60일 동안 변경이 없으면 GitHub가 예약 실행을 끔. 매년 출하기 전(6월 초)에 이 저장소의 Actions 탭 → "복숭아 가격 수집" → **Enable workflow**를 눌러 둘 것. 같은 화면의 **Run workflow**로 바로 시험해 볼 수도 있음.
